** MiniDB **
## Базовая версия

Нужен Python 3.8 или новее. Внешних зависимостей нет.

Запуск из папки проекта:

```sh
python3 main.py
```

Пример сеанса (это собственные CLI-команды, SQL-синтаксис из заметок выше пока не реализован):

```text
open data/demo
create datasets id:INT:PK name:STRING task:STRING size:INT
create models id:INT:PK name:STRING version:STRING
create experiments id:INT:PK dataset_id:INT model_id:INT accuracy:FLOAT status:STRING
insert datasets 1 "Тестовый датасет" classification 1000
insert models 1 "Simple Model" v1
insert_many models 2 "Модель A" v1 3 "Модель B" v2 4 "Модель C" v1
insert experiments 1 1 1 0.91 completed
tables
select datasets
select experiments
exit
```

Запустите программу снова, выполните `open data/demo` и `select datasets`:
схема и записи сохраняются после выхода. Относительный путь базы считается от
текущей рабочей папки. ID вводятся явно; повтор PRIMARY KEY запрещён.
Значения при вставке передаются в порядке объявления полей. Для строк с пробелами
нужны кавычки, для FLOAT используется точка. Имена таблиц и полей: латинские
буквы, цифры и `_`, первый символ — буква или `_`.

### Устройство

- `main.py` — цикл ввода, разбор команд через `shlex`, вывод таблиц.
- `database.py` — создание таблиц, проверка типов и PK, чтение/запись файлов.
- `<таблица>.schema` — текстовый CSV с именем, типом и отметкой PK для каждого поля.
- `<таблица>.csv` — значения записей без заголовка; кавычки, запятые и переносы
  строк обрабатывает стандартный модуль `csv`.

Это начальный этап, а не выполнение всего ТЗ. Пока нет автоматических ID, JOIN и индексов.
Работа с одной базой из нескольких процессов одновременно не поддерживается.

Проверки: `python3 -m unittest discover -s tests -v`.

### Фильтры SELECT

```text
select datasets where size >= 1000
select models where name = "Модель A"
select experiments where accuracy > 0.9
select experiments where status != running
```

Доступны `=`, `!=`, `>`, `<`, `>=`, `<=`. Поле, оператор и значение разделяются
пробелами. Пока поддерживается одно условие на команду. Ключевое слово `where`
не зависит от регистра. Без условия `select ТАБЛИЦА` выводит все записи.

Значение условия преобразуется к типу поля: числа сравниваются как числа,
строки — с учётом регистра, для `<` и `>` в лексикографическом порядке.
Неизвестное поле, оператор или неверный тип значения вызывают понятную ошибку,
даже если таблица пустая. При отсутствии совпадений выводится `Записей: 0`.
Фильтрация не изменяет файлы базы.

Из Python: `db.select("datasets", where=("size", ">=", "1000"))`.

### Изменение и удаление записей

```text
update datasets set size 2000 where id = 1
update models set name "Новое имя" where id = 2
delete experiments where accuracy < 0.8
```

`update` изменяет одно поле во всех подходящих записях. `delete` удаляет все
подходящие записи, сохраняя таблицу и её схему. Фильтры такие же, как у `select`:
одно условие с оператором `=`, `!=`, `>`, `<`, `>=`, `<=`.
Вокруг оператора нужны пробелы. Команды выводят количество обработанных записей.
Без совпадений выводится 0, файл не перезаписывается.

Без `where` операция применяется ко **всем записям** таблицы:

```text
update experiments set status completed
delete experiments
```

Перед UPDATE проверяются поля, типы и уникальность PRIMARY KEY во всей
итоговой таблице. При ошибке операция отменяется целиком. UPDATE и DELETE
сохраняют данные через временный файл с последующей заменой исходного файла.
После перезапуска изменения остаются в базе.

Из Python: `db.update("datasets", {"size": "2000"}, where=("id", "=", "1"))`
и `db.delete("datasets", where=("size", "<", "100"))`.
Методы возвращают количество обработанных записей; в `changes` у `update`
можно передать несколько полей.
