# PyMiniDB

Учебная файловая мини-СУБД на Python: собственный CLI, полный CRUD, типы
INT/STRING/FLOAT, первичные ключи, автоматические ID и связи трёх таблиц.

## Запуск

Нужен Python 3.8+. Внешних зависимостей у приложения и тестов нет.
Все команды ниже запускаются из папки проекта.

```sh
python3 main.py
```

```text
open data/sample
tables
select datasets
select experiments where accuracy >= 0.85
exit
```

В `data/sample` приложена база с 5 датасетами, 5 моделями и 20 экспериментами.
Чтобы получить новую такую же базу, используйте **новую** папку:

```sh
python3 seed.py data/my_demo
```

Генератор воспроизводим и отказывается перезаписывать существующую папку.
`open` создаёт отсутствующую папку или открывает имеющуюся; относительный путь
отсчитывается от текущей рабочей папки, пути с пробелами заключаются в кавычки.

## Команды

| Команда | Назначение |
| --- | --- |
| `open ПАПКА` | Создать/открыть базу |
| `create ТАБЛИЦА ПОЛЕ:ТИП:PK ...` | Создать таблицу с одним PK |
| `tables` | Показать имена таблиц |
| `insert ТАБЛИЦА ЗНАЧЕНИЯ ...` | Добавить одну запись |
| `insert_many ТАБЛИЦА [--auto-id] ЗНАЧЕНИЯ ...` | Добавить пакет |
| `select ТАБЛИЦА [where ПОЛЕ ОП ЗНАЧЕНИЕ]` | Прочитать записи |
| `update ТАБЛИЦА set ПОЛЕ ЗНАЧЕНИЕ [where ПОЛЕ ОП ЗНАЧЕНИЕ]` | Изменить поле |
| `delete ТАБЛИЦА [where ПОЛЕ ОП ЗНАЧЕНИЕ]` | Удалить записи |
| `help`, `exit` | Справка, выход |

`set` используется без знака `=`.
Строки с пробелами заключаются в кавычки, дробные числа записываются с точкой.
Имена полей и таблиц: латинские буквы, цифры и `_`; первый символ - буква или `_`.

### Создание и вставка

Пример для новой базы:

```text
open new_database
create datasets id:INT:PK name:STRING task:STRING size:INT
create models id:INT:PK name:STRING version:STRING
create experiments id:INT:PK dataset_id:INT model_id:INT accuracy:FLOAT status:STRING
insert models 10 "Ручной ID" v1
insert datasets "Новый датасет" classification 1000
insert models "Модель A" v1
insert experiments 1 1 0.91 running
insert_many models --auto-id "Модель B" v1 "Модель C" v2
```

Значения идут в порядке объявления полей. При одиночной вставке для `id:INT:PK`
можно опустить ID: передайте на одно значение меньше. В массовой вставке режим
пропуска ID выбирается явно через `--auto-id`; без флага каждая запись содержит
все поля. Пакет пишется одной строкой, без разделителей между записями.

Авто-ID равен максимуму текущих и ручных ID всего пакета плюс 1, начиная с 1.
После удаления максимального ID его номер может использоваться снова; отдельного
счётчика нет. В Python `insert_many` допускает смешанный пакет с ручными и авто-ID.
Для других PK автоматическое назначение не поддерживается.

### Фильтры, изменение и удаление

```text
select experiments where accuracy >= 0.9
select models where name = "Модель A"
update experiments set status completed where id = 1
delete experiments where id = 1
```

Поддерживается одно условие: `=`, `!=`, `>`, `<`, `>=`, `<=`.
Вокруг оператора нужны пробелы.
Числа сравниваются как числа, строки - с учётом регистра, в лексикографическом порядке.
Без совпадений выводится 0.
Без `where` SELECT читает все записи.
Без `where` UPDATE и DELETE обрабатывают всю таблицу.
DELETE сохраняет схему таблицы.
Для удаления таблиц, баз надо удалять руками соответствующие файлы.

### Ключи и связи

У таблиц `datasets`, `models`, `experiments` требуется `id:INT:PK`,
у `experiments` также `dataset_id:INT` и `model_id:INT`.
Связи заданы в программе: `experiments.dataset_id → datasets.id`,
`experiments.model_id → models.id`. Родители должны существовать перед вставкой
эксперимента. Отдельного синтаксиса объявления FK нет.

Дубликаты PK и неверные ссылки отклоняются.
У родителя нельзя удалить или изменить его ID, пока на него ссылаются эксперименты.
Можно изменить остальные поля, переназначить эксперимент на существующего родителя или сначала удалить детей.
Каскадных операций нет.
При ошибке проверки весь пакет/UPDATE/DELETE отменяется.

## Архитектура и файлы

- `main.py`: ввод, разбор через `shlex`, вывод и сообщения об ошибках.
- `database.py`: типы, PK/FK, CRUD, автоматические ID и файловое хранение.
- `seed.py`: воспроизводимое создание базы 5/5/20.
- `demo.py`: создание отдельной тестовой базы и автоматическая демонстрация.
- `tests/`: модульные проверки и запуски CLI отдельными процессами.
- `docs/schema.dbml`: схема для импорта в dbdiagram.

Каждая база - папка. Для таблицы создаются два UTF-8 файла:

```text
models.schema          models.csv
id,INT,PK              1,Модель A,v1
name,STRING,
version,STRING,
```

`.schema` содержит CSV-строки `имя,тип,маркер PK`, `.csv` - значения без заголовка.
Запятые, кавычки и переносы строк экранирует стандартный модуль `csv`.
Чтение выполняется последовательным проходом. Вставка, изменение и удаление
готовят итоговую таблицу в памяти и записывают временный файл в папке базы,
затем заменяют исходный файл. Ошибка проверки или замены сохраняет прежние данные.

## Проверка и защита

```sh
python3 -m unittest discover -s tests -v
python3 demo.py
```

На этапе подготовки прошёл **41 тест**. Проверяются CRUD, все операторы,
типы, PK/FK, авто-ID, массовые операции, отмена при ошибках, сбой замены файла,
перезапуск/EOF, данные из поставки и полный сценарий защиты.

`demo.py` сам создаёт базу 5/5/20 в папке `demo` рядом со скриптом
(при повторных запусках - `demo_2`, `demo_3` и т.д.), запускает два процесса CLI,
показывает команды/ответы, проверяет 7 ожидаемых ошибок PK/FK и сохранность данных,
База после показа сохраняется; её путь и команда `open` выводятся в терминале.
Основные данные не затрагиваются.
